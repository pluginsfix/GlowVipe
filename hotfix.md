# 🛠️ Hotfix & Security Audit: GlowVipe (v1.0.0)

Полный отчёт по исправленным багам, дюпам и уязвимостям оригинального плагина **GornaVipe** при разработке и рефакторинге в **GlowVipe**.

---

## 1. 🛑 Дюп с барьером при покупке второго слота (GUI Barrier Dupe)

### Причина в оригинале:
При покупке слота №2 вызывался метод `openGornaMenu(player)`. Открытие нового инвентаря приводило к принудительному закрытию старого меню со стороны клиента и сервера, вызывая событие `InventoryCloseEvent`. 

В обработчике `onInventoryClose` выполнялся цикл по количеству купленных слотов:
```java
int purchasedSlots = storageConfig.getInt(uuid + ".purchased_slots", 0); // уже равно 2
for (int i = 0; i < purchasedSlots; i++) {
    ItemStack item = event.getInventory().getItem(storageIndices[i]);
    if (item != null && item.getType() != Material.AIR && item.getType() != Material.LIGHT_GRAY_STAINED_GLASS_PANE) {
        storageConfig.set(uuid + ".slots." + i, itemToBase64(item));
    }
}
```
Так как в старом инвентаре во 2-м слоте (`storageIndices[1]`) физически находился предмет `Material.BARRIER`, проверка `item.getType() != Material.LIGHT_GRAY_STAINED_GLASS_PANE` проходила успешно. Плагин сериализовал `BARRIER` в `data.yml` как сохранённый предмет игрока. При следующем открытии хранилища слот загружал барьер как настоящий предмет, позволяя игроку забрать его в свой инвентарь.

### Решение в GlowVipe:
1. **In-Place обновление меню:** При покупке слота интерфейс обновляется на месте (`menu.renderStorageSlots(topInventory, data)`), без вызова `openInventory` и закрытия окна.
2. **PDC-валидация элементов:** Все служебные предметы (заполнители, пустые слоты, барьеры, кнопки) маркируются через `PersistentDataContainer` с уникальным ключом `NamespacedKey(plugin, "gui_element")`. Предметы интерфейса физически не могут быть сохранены в хранилище.
3. **Строгая блокировка кликов:** Запрещено любое взаимодействие и перемещение барьеров и заполнителей.

## 2. ⚡ Дюп при быстром клике / автокликере на кнопку «Распаковать» (Unpack Spam Dupe)

### Причина в оригинале:
В оригинальном коде отсутствовал дебаунс (click cooldown) и атомарность операций:
1. Игрок использовал автокликер или отправлял два пакетных клика в один игровой тик на кнопку «Распаковать».
2. Обработчик `handlePackUnpack(player, uuid, inv, true)` считывал предметы из конфигурации дважды до того, как успевала выполниться очистка или закрытие инвентаря.
3. В результате игрок получал удвоенное (или утроенное) количество сохранённых ресурсов.

### Решение в GlowVipe:
1. **Click Debounce (150 мс):** Каждый клик в GUI фильтруется по временной метке через `ConcurrentHashMap<UUID, Long>`.
2. **Атомарная очистка данных:** Данные в кэше и репозитории очищаются в рамках единой транзакции метода `unpack()`.

## 3. 🎭 Уязвимость подделки меню по заголовку (Title Spoofing & Desync)

### Причина в оригинале:
Проверка принадлежности меню осуществлялась через прямое сравнение строкового заголовка:
```java
if (!event.getView().getTitle().equals(title)) return;
```
При этом в `onClick` дефолтный заголовок был `&7Вайповое Хранилище`, а в `onClose` — `&5GornaVipe — Хранилище`. Любое переименование наковальней, сундуком или локализацией могло либо сломать сохранение, либо вызвать сброс чужих данных.

### Решение в GlowVipe:
- Создан кастомный держатель инвентаря `GlowVipeHolder implements InventoryHolder`.
- Проверка меню выполняется строго типизированно:
```java
if (!(event.getInventory().getHolder() instanceof GlowVipeHolder holder)) return;
```

## 4. 🖱️ Дюпы через Drag, NumberKey и Shift-Click

### Причина в оригинале:
1. Событие `InventoryDragEvent` не обрабатывалось вовсе, что позволяло протаскивать предметы через слоты меню с искажением их количества.
2. Использование цифровых клавиш (`HOTBAR_SWAP` / `NumberKey`) и смены второй руки (`SwapOffhand`) приводило к замене предметов меню на предметы из хотбара.
3. Shift-Click из инвентаря игрока блокировался некорректно.

### Решение в GlowVipe:
1. `InventoryDragEvent` полностью перехватывается и отменяется для всех слотов верхнего меню (`rawSlot < 27`).
2. Обработаны все взаимодействия клавиатуры (`event.getClick().isKeyboardClick()`) с безопасной заменой и сохранением.
3. Shift-Click из инвентаря игрока корректно ищет свободный разблокированный слот в хранилище либо складывает в существующий стак.

## 5. ⏱️ Фризы главного потока сервера при синхронном I/O

### Причина в оригинале:
При каждом клике, покупке слота, запаковке или закрытии меню плагин синхронно в главном потоке сервера перезаписывал файл `data.yml` через `storageConfig.save(storageFile)`. На активном сервере это вызывало резкие просадки TPS и лаг-спайки.

### Решение в GlowVipe:
- Реализован `YamlVaultRepository` с in-memory кэшированием (`ConcurrentHashMap`).
- Изменения сохраняются в оперативной памяти мгновенно, а запись на диск (`config.save`) выполняется асинхронно в фоновом потоке шедулера.

## 6. 🎨 Стандартизация и соответствие `minecraft-plugin-craft-maven`

- **Стек:** Java 21 LTS, Paper 1.21 API, Adventure Component API.
- **Чистота кода и конфигов:** Полный запрет на комментарии (`//`, `/* */`, `#`).
- **Тексты и сообщения:** Полное отсутствие захардкоженных строк в Java-коде. Все сообщения и интерфейсы вынесены в `messages.yml` и `config.yml`.
- **Типографика:** Полное отключение курсива (`<!italic>`, `TextDecoration.ITALIC = false`). Фирменные маркеры `&#FB8808▶` и `&#FFFF00◆`.
- **Безопасные хуки:** Интеграция с Vault Economy через `ServiceRegisterEvent` без использования `disablePlugin(this)`.
